## Part 1：环境准备（0 → 1）

### 1.1 软件版本要求

| 软件 | 版本 | 说明 |

| **Node.js** | **20 LTS** | 推荐从 [nodejs.org](https://nodejs.org/) 安装 |

验证安装：


>
> ```powershell

> ```

### 1.2 打开项目并安装依赖

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement"

cd backend
npm install

cd ..\frontend
npm install
```

### 1.3 创建 MySQL 数据库与用户

**本机 MySQL 路径（示例）**：`C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe`  
请用 **root 账号**登录 MySQL（密码为你安装时自行设定的，**勿写入文档或 Git**）：

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u root -p
```

在 MySQL 提示符下执行（开发环境可用示例密码 `reimb123`；**生产务必换强密码**）：

```sql
CREATE DATABASE IF NOT EXISTS reimbursement
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'reimb'@'localhost' IDENTIFIED BY 'reimb123';
GRANT ALL PRIVILEGES ON reimbursement.* TO 'reimb'@'localhost';
FLUSH PRIVILEGES;
```

验证应用账号可连：

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u reimb -preimb123 -e "SELECT 1 AS ok;"
```

> ⚠️ **常见坑**：`-p` 与密码之间**不能有空格**（`-preimb123`）。若你改了密码，须同步修改 `backend\.env` 中的 `DB_PASSWORD`。

### 1.4 创建 backend/.env

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\backend"
copy .env.example .env
notepad .env
```

**开发最小配置**（按需修改）：

| 变量 | 开发示例值 | 说明 |
|------|------------|------|
| `DB_HOST` | `127.0.0.1` | 本机 MySQL |
| `DB_PORT` | `3306` | |
| `DB_USER` | `reimb` | |
| `DB_PASSWORD` | `reimb123` | 与上一步 SQL 一致 |
| `DB_NAME` | `reimbursement` | |
| `FRONTEND_URL` | `http://localhost:5173` | 不含 `/h5/` 后缀 |
| `JWT_SECRET` | 随机长字符串 | 生产用 `openssl rand -base64 48` |
| `DINGTALK_*` | 可先留占位符 | Part 4 再填真实值 |

钉钉凭证占位时可先开发；免登/OA 真机能力需 Part 4 配置后再测。

## Part 2：本机首次跑通（1 → 2）

### 2.1 初始化数据库（仅首次）


> ⚠️ **dev 默认审批模式 A**：`db:seed` 在非 production 下会把 `approval.mode` 设为 **A**（自研 H5 审批），因为 `dev_user` 不是真实钉钉用户，无法发起 OA。这是**正常行为**，见 Part 5。

### 2.2 启动后端（终端 1）

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\backend"

```

期望：`[backend] P0 running at http://localhost:3000`（health 接口 `phase` 可能为 P3/P5，以实际为准）。

### 2.3 启动前端（终端 2，缺一不可）

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\frontend"
npm run dev
```

期望：`Local: http://localhost:5173/h5/`

浏览器打开：**http://localhost:5173/h5/**

> ⚠️ **常见坑 · ERR_CONNECTION_REFUSED**
>
> - 只跑了 `npm run build` **不会**占用 5173 端口，开发必须用 `npm run dev`。
> - 必须**两个终端**同时运行 backend + frontend。

### 2.4 开发登录与完整审批流程

非钉钉浏览器会自动调用 `POST /api/auth/dev-login`，默认身份 **开发测试员**（`dev_user`）。

| 步骤 | 操作 |
|------|------|
| 1 | 首页 → **新建报销** → 选项目、科目、金额、发票号 → 保存 |
| 2 | （可选）上传 PDF 附件 |
| 3 | **提交** → 状态变为「审批中」 |
| 4 | 底部 **我的** → **开发角色切换** → 点 **项目经理 dev_manager** |
| 5 | **待办** Tab → 找到刚提交的单 → **通过** |
| 6 | 若还有财务节点：再切回 **员工 dev_user** → 待办 → 财务通过 |
| 7 | 回到报销详情，确认状态「已通过」、审批时间线完整 |

### 4.4 OA 审批模板（字段名必须一字不差）

在钉钉管理后台 → **OA 审批** → 创建表单，控件 **名称（label）** 须与下表完全一致（详见 [P4-OA对接指南](./P4-OA对接指南.md) §2）：

| 模板控件名称 | 类型 |
|--------------|------|
| 报销单号 | 单行文本 |
| 项目编号 | 单行文本 |
| 项目名称 | 单行文本 |
| 费用类型 | 单行文本 |
| 报销金额 | 数字 |
| 费用发生日期 | 日期 |
| 报销说明 | 多行文本 |
| 详情链接 | 单行文本 |
| 发票及凭证 | 单行文本或附件* |

\* 免费方案下附件存本地，系统将**文件名写入文本**；审批人通过「详情链接」打开 H5 下载真实文件。若模板用「附件」作控件名，设置 `DINGTALK_OA_ATTACHMENT_LABEL=附件`。

配置审批链（如：项目经理 → 区域财务）→ **发布** → 复制 **processCode**（`PROC-XXXX-XXXX`）：

```env
DINGTALK_PROCESS_CODE=PROC-XXXX-XXXX
```

### 4.5 事件订阅（二选一或并存）

#### 方式 A：Stream（推荐，免公网）

1. 开发者后台 → 开发配置 → **事件订阅** → **Stream 模式**
2. 订阅事件：**`bpms_instance_change`**
3. `.env`：`DINGTALK_STREAM_ENABLED=true`
4. 重启 backend，日志应出现：`[stream] 钉钉事件 Stream 已连接`

#### 方式 B：HTTP 回调（需公网 HTTPS）

1. 回调 URL：`https://<域名>/api/webhooks/dingtalk/oa`
2. 配置 Token、EncodingAESKey → 写入：
   ```env
   DINGTALK_CALLBACK_TOKEN=...
   DINGTALK_CALLBACK_AES_KEY=...
   ```
3. 保存后钉钉会发 URL 验证，后端自动响应

### 4.6 生产审批模式 B

开发 seed 默认 **A**；生产须 **B**（钉钉 OA）：

```env
NODE_ENV=production
APPROVAL_MODE=B
DINGTALK_PROCESS_CODE=PROC-...
```

或在库中：

```sql
UPDATE sys_config SET config_value = 'B' WHERE config_key = 'approval.mode';
```

验证：

```powershell
curl http://localhost:3000/api/config/approval
# 期望 processCodeConfigured: true, mode: B
```

> ⚠️ **常见坑 · dev_user OA 降级**
>
> 即使用户配置了 processCode，**dev_user 提交仍会走方案 A**，因为不是真实钉钉 userid。真机联调须用**真实员工**在钉钉 H5 内提交。

## Part 5：联调验证（4 → 5）

### 5.1 钉钉客户端真机流程

| 步骤 | 检查点 |
|------|--------|
| 1 | 应用已发布，可见范围含测试员工 |
| 2 | 工作台打开微应用 → 自动免登（非 dev-login） |
| 3 | 新建并提交报销 |
| 4 | 钉钉 **OA 审批** 出现对应单据 |
| 5 | 审批人同意/驳回 |
| 6 | H5 详情状态同步；通过时预算占用 |

### 5.2 无真机时的部分测试：simulate-oa-event

先以 mode B 提交一单（或手动写入 `dingtalk_oa_mapping`），再模拟事件：

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\backend"

# 内存直调服务层
node scripts/simulate-oa-event.js --reimbId=1 --type=finish --result=agree

# 经 HTTP webhook（与 verify:p4-http 一致）
node scripts/simulate-oa-event.js --reimbId=1 --type=finish --result=agree --http=true
```

`type`：`start` | `finish` | `terminate` | `delete`  
`finish` 时 `result`：`agree` | `refuse`

### 5.3 联调后再跑验证

```powershell
cd backend
npm run verify:p4
npm run verify:all
```

### 5.4 常见错误与修复

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 免登失败 / 无效 clientId | AppKey/Secret 错误或应用未发布 | 核对 `.env`；检查应用可见范围 |
| 提交后无 OA 单 | processCode 空、权限不足、仍为 mode A | 设 `approval.mode=B`；查 `dingtalk_oa_mapping.sync_status` |
| OA 发起失败 | 模板字段名不一致 | 对照 Part 4.4 逐字核对 label |
| 审完状态不变 | Stream 断连 / 未订阅事件 | 重启 backend；确认订阅 `bpms_instance_change` |
| `[notify] 无效的clientId或者clientSecret` | 凭证占位或 Secret 错误 | 更新凭证；不影响审批主流程时可暂忽略 |
| dev 环境永远 mode A | 设计如此 | 用钉钉真机测 mode B |
| HTTP 回调验证失败 | 非 HTTPS / URL 不可达 | 上 HTTPS 反代；检查防火墙 |

排查 OA 映射：

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u reimb -preimb123 reimbursement -e "SELECT reimbursement_id, process_instance_id, sync_status FROM dingtalk_oa_mapping ORDER BY id DESC LIMIT 5;"
```
