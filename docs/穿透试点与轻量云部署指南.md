## 总体路线

| 阶段 | 周期 | 基础设施 | 用户规模 | 目标 |
|------|------|----------|----------|------|
| **阶段一 · 穿透试点** | 1–2 周 | 本机 Windows + MySQL + cpolar/natapp 穿透 | 5–10 人 | 验证钉钉免登、OA 审批、Stream 回写、业务流程 |
| **阶段二 · 轻量云正式** | 长期 | 阿里云/腾讯云轻量 2C2G + Docker（或 PM2+Nginx）+ 固定域名 HTTPS | 全公司 | 7×24 可用、数据持久、备份与运维 |

**推荐顺序**：

1. 本机跑通 `verify:e2e` → 配置钉钉应用与 OA 模板（见 [钉钉部署详细步骤](./钉钉部署详细步骤.md) A–F 节）
2. 阶段一：cpolar 穿透 + 5–10 人真机联调，收集问题
3. 阶段二：购买轻量云 → 部署 Docker → 迁移试点数据 → 切换钉钉域名 → 全量上线

> **为何分两阶段？** 穿透方案零云成本、上线快，适合验证业务；但 PC 需常开、域名可能变化、不适合生产。正式环境需固定 HTTPS 域名与自动化备份。

#### 方案 B：穿透 8080 + 本机 Nginx 反代（推荐试点）

更接近生产：Nginx 统一对外，静态 H5 + `/api` 反代 backend。

**步骤 1** — 构建前端静态资源：

```powershell

```

**步骤 2** — 本机 Nginx（示例监听 8080）

参考 `deploy/nginx.conf`，将 `proxy_pass http://backend:3000` 改为 `http://127.0.0.1:3000`，`root` 指向含 `h5\` 的目录（例如把 `frontend\dist` 内容部署到 `C:\nginx\html\`，访问路径为 `/h5/`）。

简化 `server` 块要点：

```nginx
listen 8080;
location /h5/ {
    alias C:/nginx/html/h5/;   # 或 root 配置，与 dist 结构一致
    try_files $uri $uri/ /h5/index.html;
}
location /api/ {
    proxy_pass http://127.0.0.1:3000/api/;
}
```

### 1.5 穿透方案限制与风险

| 限制 / 风险 | 说明 | 缓解 |
|-------------|------|------|
| **PC 需常开** | 关机或休眠后穿透失效，全员无法访问 | 试点期保持开机；正式上云 |
| **免费域名变化** | cpolar 免费子域重启可能变 | 升级固定域名；或每次更新钉钉配置 |
| **带宽与延迟** | 经第三方中继，上传附件较慢 | 控制试点人数；正式用云带宽 |
| **安全** | 公网暴露开发/试点环境 | **仅试点**；强 JWT；不用弱密码；限制可见范围 |
| **无 SLA** | 穿透服务或本机故障即停服 | 阶段二迁移至轻量云 |
| **数据在本机** | 硬盘故障无异地备份 | 试点期每日 `mysql-backup.ps1` |
| **不适合压测** | 并发受限 | 正式环境再测 |

> 穿透试点**目标**是验证业务流程与钉钉集成，**不是**长期生产方案。试点结论 OK 后进入阶段二。

| 云厂商 | 规格建议 | 参考价格 | 系统 |

### 2.2 域名与 HTTPS

#### 2.2.1 备案说明（中国大陆）

| 场景 | 要求 |
|------|------|
| 服务器在**大陆** + 域名 **.cn / .com 等国内接入** | **ICP 备案**通常 7–20 个工作日 |
| 香港/海外节点 | 可免备案，但钉钉用户在大陆访问可能略慢 |
| 仅 IP + 自签证书 | **不可用于钉钉 H5**（须可信 HTTPS） |

建议：正式部署前**提前提交备案**；备案审核期间可用阶段一穿透继续试点。

#### 2.2.2 证书获取

| 方式 | 说明 |
|------|------|
| **Let's Encrypt** | 免费，Certbot 或 acme.sh 自动续期（Nginx/Caddy） |
| **云厂商免费证书** | 阿里云/腾讯云 SSL 控制台申请，绑定轻量/LB |
| **Cloudflare** | 可选 CDN + 边缘证书（源站仍需 HTTPS） |

正式 `FRONTEND_URL` 示例：`https://reimb.example.com`（**无** `/h5/` 后缀）。

| 钉钉 H5 首页 | `https://xxxx.cpolar.cn/h5/` | `https://reimb.example.com/h5/` |
| 安全域名 | `xxxx.cpolar.cn` | `reimb.example.com` |
| `FRONTEND_URL` | `https://xxxx.cpolar.cn` | `https://reimb.example.com` |
| HTTP 回调（若启用） | `https://xxxx.cpolar.cn/api/webhooks/dingtalk/oa` | `https://reimb.example.com/api/webhooks/dingtalk/oa` |

**无需修改**：

- `DINGTALK_PROCESS_CODE`（OA 模板未重建则不变）
- AppKey / AppSecret / AgentId / CorpId
- Stream 订阅事件（改域名后**重启 backend** 即可）

**切换步骤**：

1. 正式环境 `verify:all` 或 health-check 通过
2. 更新 `.env` 中 `FRONTEND_URL` → 重启 backend / `docker compose restart backend`
3. 钉钉开放平台更新 H5 首页 + 安全域名 → 发布新版本
4. 扩大可见范围至全员
5. 通知员工**完全退出并重启钉钉**（清除 H5 缓存）

```powershell
curl https://reimb.example.com/api/config/approval
# 期望 mode:B, streamConnected:true, processCodeConfigured:true
```

### 2.5 数据迁移（试点 → 正式）

试点数据在本机 MySQL + `backend/uploads/` 时，迁移至云服务器。

#### 2.5.1 MySQL 备份（本机）

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement"

.\scripts\backup\mysql-backup.ps1 -EnvFile backend\.env
```

备份默认路径：`backups\mysql\reimbursement-YYYYMMDD-HHmmss.sql.gz`

#### 2.5.2 上传至服务器

```powershell
# 示例：scp 到 Linux（需替换 IP 与路径）
scp "f:\obsidian知识库\cursor\dingtalk-reimbursement\backups\mysql\reimbursement-20260701-020000.sql.gz" root@<服务器IP>:/opt/dingtalk-reimbursement/backups/mysql/
```

或使用 WinSCP / 云盘中转。

#### 2.5.3 附件备份与上传

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement"
.\scripts\backup\backup-uploads.ps1
# 产物在 backups\uploads\
scp backups\uploads\*.zip root@<服务器IP>:/opt/dingtalk-reimbursement/backups/uploads/
```

#### 2.5.4 服务器恢复

**Linux（Docker 栈）**：

```bash
# 停止 backend 避免写入冲突
docker compose -f docker-compose.prod.yml stop backend

# 恢复 MySQL（示例）
./scripts/backup/mysql-restore.sh --env .env --backup backups/mysql/reimbursement-20260701-020000.sql.gz

# 恢复附件到 Docker volume 或挂载目录
# docker compose exec backend sh -c "cd /app/uploads && unzip /path/to/uploads-xxx.zip"
```

**Windows 服务器**：

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement"
# 先 pm2 stop reimb-backend
.\scripts\backup\mysql-restore.ps1 -EnvFile backend\.env -BackupFile "backups\mysql\reimbursement-20260701-020000.sql.gz"
# 解压 uploads zip 到 backend\uploads\
pm2 start reimb-backend
```

### 2.6 上线后运维

日常操作详见 **[管理员手册](./管理员手册.md)** §6–§7；以下为正式环境必做项。

#### 2.6.1 备份计划

| 对象 | 频率 | 脚本 |
|------|------|------|
| MySQL | 每日 02:00 | `mysql-backup.ps1` / `mysql-backup.sh` |
| 附件 uploads | 每日或每周 | `backup-uploads.ps1` / `backup-uploads.sh` |
| 恢复演练 | 每季度 | `mysql-restore.*` 在测试库验证 |

**Linux cron 示例**（[管理员手册](./管理员手册.md) §6.4）：

```cron
0 2 * * * /opt/dingtalk-reimbursement/scripts/backup/mysql-backup.sh --env /opt/dingtalk-reimbursement/.env
30 2 * * * /opt/dingtalk-reimbursement/scripts/backup/backup-uploads.sh
```

**Windows 任务计划程序**：见 [从零到钉钉部署-实操指南](./从零到钉钉部署-实操指南.md) Part 6.4。

#### 2.6.2 健康巡检

```powershell
.\scripts\deploy\health-check.ps1 -BackendUrl https://reimb.example.com/api -FrontendUrl https://reimb.example.com
```

或 cron + 告警：

```bash
curl -sf https://reimb.example.com/api/health | jq '.ok,.db'
```

关注指标：`db: true`、`streamConnected: true`（`/api/config/approval`）、磁盘 `uploads/` 与 `backups/`。

#### 2.6.3 重启与日志

```bash
# Docker
docker compose -f docker-compose.prod.yml restart backend
docker compose -f docker-compose.prod.yml logs -f backend --tail 100
```

```powershell
# PM2
pm2 restart reimb-backend
pm2 logs reimb-backend --lines 100
```

OA 故障时临时切方案 A，恢复后切回 B — 见 [管理员手册](./管理员手册.md) §7。
