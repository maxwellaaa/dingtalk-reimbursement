## 2. Docker 生产部署（Linux 服务器推荐）

```bash
cd dingtalk-reimbursement
cp .env.production.example .env
# 编辑 .env：MySQL 密码、钉钉凭证、JWT_SECRET、FRONTEND_URL

docker compose -f docker-compose.prod.yml up -d --build

# 首次初始化数据库（在 backend 容器或宿主机执行）
docker compose -f docker-compose.prod.yml exec backend sh -c "cd /app && node scripts/init-db.js"
# 若镜像未含 scripts，在宿主机：
cd backend && cp ../.env .env && npm run db:init && npm run db:seed-prod

# 健康检查
curl -s http://localhost:8080/api/health
curl -s http://localhost:8080/healthz
```

访问：`http://<服务器IP>:8080/h5/`（生产请前置 HTTPS 反代）

停止 / 重启：

```bash
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml restart backend
```

## 3. 非 Docker 部署（Windows Server / Linux + 本机 MySQL）

适用：本机 MySQL 8/9.7、Docker/WSL 不可用（当前开发机场景）。

### 3.1 准备

1. 安装 Node.js 20 LTS、MySQL 8+、（可选）Nginx、PM2  
2. 创建库与用户（密码自行设定，勿使用示例 `reimb123` 上生产）：

```sql
CREATE DATABASE reimbursement DEFAULT CHARACTER SET utf8mb4;
CREATE USER 'reimb'@'localhost' IDENTIFIED BY '你的强密码';
GRANT ALL ON reimbursement.* TO 'reimb'@'localhost';
FLUSH PRIVILEGES;
```

3. 配置环境：

```powershell
cd dingtalk-reimbursement\backend
copy .env.example .env
# 填写 DB_*、钉钉凭证、JWT_SECRET、FRONTEND_URL
```

### 3.2 初始化

```powershell
cd dingtalk-reimbursement
.\scripts\deploy\init-production.ps1 -EnvFile backend\.env
```

### 3.3 启动后端

**方式 A — PM2（Linux / 可装 PM2 的 Windows）**

```bash
cd backend && npm ci --omit=dev
pm2 start ../deploy/ecosystem.config.cjs
pm2 save
```

**方式 B — 直接 node**

```powershell
cd backend
$env:NODE_ENV="production"
npm start
```

### 3.4 前端静态资源

```powershell
cd frontend
npm ci
npm run build
# dist/ 由 Nginx 托管到 /h5/，参考 deploy/nginx.conf
```

Nginx `root` 指向 `frontend/dist` 的**父目录**（与 Docker 相同：`/usr/share/nginx/html` 下含 `h5/` 子目录）。  
将 `deploy/nginx.conf` 中 `proxy_pass http://backend:3000` 改为 `http://127.0.0.1:3000`。

### 3.5 健康检查

```powershell
.\scripts\deploy\health-check.ps1 -BackendUrl http://localhost:3000 -FrontendUrl http://localhost:8080
```

## 4. 本地快速验证（备份脚本）

```powershell
cd dingtalk-reimbursement

# 仅打印参数，不写文件
.\scripts\backup\mysql-backup.ps1 -EnvFile backend\.env -DryRun

# 对本机 MySQL 执行备份（需 backend\.env 中 DB_* 正确且 mysqldump 在 PATH）
.\scripts\backup\mysql-backup.ps1 -EnvFile backend\.env

.\scripts\backup\backup-uploads.ps1
```

备份默认目录：`backups/mysql/`、`backups/uploads/`（已在 `.gitignore`）

## 5. 自动化 vs 手工

| 任务 | 脚本/Compose | 需人工 |
|------|----------------|--------|
| 建库建表 | `init-production.*` | 首次创建 MySQL 用户 |
| 生产配置 | `seed-prod.js` | 填写 `.env`、钉钉后台 |
| 业务数据 | — | 录入 project、budget、审批流 |
| 容器编排 | `docker-compose.prod.yml` | 服务器、域名、HTTPS 证书 |
| 每日备份 | `mysql-backup.*`、`backup-uploads.*` | 配置计划任务 / cron |
| 恢复演练 | `mysql-restore.*` | 确认备份文件、停服窗口 |
| 钉钉 OA | — | 模板、processCode、Stream |

## 6. 与开发栈差异

| 项 | 开发 | 生产 |
|----|------|------|
| Seed | `npm run db:seed`（dev_user） | `npm run db:seed-prod` |
| 审批默认 | 常降级 A | `approval.mode=B` |
| MySQL 密码 | docker-compose 示例 | `.env` 强密码 |
| 前端 | Vite :5173 | Nginx 静态 `/h5/` |
