## A. 前置条件

在开始钉钉开放平台配置前，请确认以下条件**全部满足**。

### A.1 账号与权限

1. 你拥有**钉钉企业管理员**或**子管理员（应用开发权限）**账号。
2. 企业已完成认证；**标准版**即可，无需专业版/专属版。
3. 测试员工账号已加入企业通讯录，且将被加入微应用「可见范围」。

### A.2 服务器与域名

| 环境 | HTTPS | 说明 |
|------|:-----:|------|
| 本机纯浏览器开发 | 否 | 可用 `dev-login`，**不能**测钉钉免登与真机 OA |
| 本机 + 内网穿透 | 是 | 真机联调推荐（ngrok / frp 等） |
| **生产** | **必须** | 钉钉 H5 微应用、HTTP 事件回调均要求 HTTPS |

生产环境需准备：

- 已备案（如适用）的域名，例如 `https://reimb.example.com`
- 有效 SSL 证书（Let's Encrypt / 云厂商 LB / Nginx 证书）
- 服务器可访问公网（Stream 模式**出站**即可，无需公网入站）

### A.3 本机已完成 verify:e2e

在配置钉钉之前，先在本机跑通基础能力，避免把环境问题误判为钉钉问题。

> 完整自动化验证：`npm run verify:all`（含 P3/P4 OA 模拟）。详见 [从零到钉钉部署-实操指南](./从零到钉钉部署-实操指南.md) Part 2.6。

## C. 配置 H5 微应用

### C.1 开发环境 vs 生产环境 URL

| 场景 | 钉钉「应用首页地址」 | `FRONTEND_URL`（`.env`） | 备注 |
|------|----------------------|--------------------------|------|
| 本机浏览器 | `http://localhost:5173/h5/` | `http://localhost:5173` | **不含** `/h5/` 后缀 |
| 内网穿透联调 | `https://abc.ngrok-free.app/h5/` | `https://abc.ngrok-free.app` | 须 HTTPS |
| **生产** | `https://reimb.example.com/h5/` | `https://reimb.example.com` | 须 HTTPS；与 Nginx 域名一致 |

> **重要**：`FRONTEND_URL` **不要**带 `/h5/` 后缀。系统生成详情链接时会自动拼接：`{FRONTEND_URL}/h5/reimb/{id}`。

### C.2 配置应用首页（逐步）

1. 开放平台 → 你的应用 → **应用能力** → **网页应用**（或 **H5 微应用**）。
2. 启用 **网页应用** / **H5 微应用**。
3. 填写 URL：

| 配置项 | 开发示例 | 生产示例 |
|--------|----------|----------|
| **应用首页地址**（移动端） | `http://localhost:5173/h5/` | `https://reimb.example.com/h5/` |
| **PC 端首页地址**（如有） | 同上或留空 | 同上 |
| **管理后台地址**（如有） | 可留空 | 可留空 |

4. 同步修改 `backend/.env`：

```env
FRONTEND_URL=http://localhost:5173
# 生产改为：
# FRONTEND_URL=https://reimb.example.com
```

5. 保存后 **重启 backend**。

### C.3 免登与安全域名

1. 开放平台 → **开发配置** → **安全设置**（或 **安全域名** / **可信域名**）。
2. 添加 **HTTP 安全域名**（不含路径）：

| 环境 | 添加域名 |
|------|----------|
| 开发 | `localhost` 或穿透域名主机名 |
| 生产 | `reimb.example.com` |

3. 若使用 Vite 开发服务器端口 **5173**，部分企业还需在 **JSAPI 安全域名** 中加入完整 origin（按控制台提示操作）。

4. **免登**：本系统使用钉钉 `authCode` 换 JWT，无需单独配置 OAuth 回调页；员工在钉钉客户端打开微应用即可自动登录。

### C.4 申请 API 权限（逐步）

路径：**开发配置** → **权限管理** → **添加接口权限**。

勾选并申请以下权限（名称以控制台为准，以下为标准版常见表述）：

| 分类 | 权限名称（控制台） | 用途 |
|------|-------------------|------|
| 通讯录 | **成员信息读**（`Contact.User.Read`） | 免登、用户信息 |
| 通讯录 | **部门信息读**（`Contact.Department.Read`） | 部门 ID（发起 OA 可选） |
| 工作流 / OA | **工作流实例写** / **发起审批实例** | 创建 OA 报销单 |
| 工作流 / OA | **工作流实例读**（可选） | 补偿查询实例状态 |
| 消息 | **工作通知消息** / **发送工作通知** | 审批提醒（若启用） |

**操作步骤**：

1. 在权限列表中搜索上表关键词。
2. 勾选所需权限 → **申请权限**。
3. 通知**企业主管理员**在 **钉钉管理后台** → **工作台** → **应用管理** → 找到本应用 → **审批** 通过权限申请。
4. 权限通过后，无需改代码，**重启 backend** 即可。

### C.5 设置可见范围并发布

1. **版本管理与发布** → **创建版本** → 填写版本说明 → **发布**。
2. **可见范围**：至少包含用于联调的测试员工、项目经理、财务。
3. 员工在钉钉 **工作台** 中应能看到该应用图标。

## D. 创建 OA 审批模板（逐步）

> 字段映射源码：`backend/src/services/dingtalkOa.js`（`OA_FORM_FIELDS`）与 `dingtalkNotify.js`（`buildReimbursementFormValues`）。详见 [P4-OA对接指南](./P4-OA对接指南.md) §2。

### D.1 进入 OA 审批设计器

1. 登录 [钉钉管理后台](https://oa.dingtalk.com/)（需 OA 审批管理权限）。
2. 左侧 **工作台** → **OA 审批**（或 **审批** → **OA 审批**）。
3. 点击 **创建新表单** / **创建模板**。
4. 模板名称建议：`报销申请` 或 `园林协作报销`。

### D.2 表单设计 — 逐字段添加

在 **表单设计** 拖拽控件，**控件标题（label）必须与下表完全一致**（含中文标点）。系统按 **名称** 匹配，不是按字段 ID。

| 序号 | 控件标题（label） | 控件类型 | 是否必填 | 系统填入内容 |
|:----:|-------------------|----------|:--------:|--------------|
| 1 | **报销单号** | 单行输入框 | 是 | `reimbursement.bill_no` |
| 2 | **项目编号** | 单行输入框 | 是 | `project.code` |
| 3 | **项目名称** | 单行输入框 | 是 | `project.name` |
| 4 | **费用类型** | 单行输入框 | 是 | 明细科目汇总 |
| 5 | **报销金额** | 数字输入框 | 是 | `reimburse_amount` |
| 6 | **费用发生日期** | 日期 | 是 | `expense_date`（YYYY-MM-DD） |
| 7 | **报销说明** | 多行输入框 | 否 | `description` / `title` |
| 8 | **详情链接** | 单行输入框 | 否 | H5 详情 URL（建议设为只读） |
| 9 | **发票及凭证** | 单行输入框 **或** 附件 | 否 | 附件**文件名**列表（见下文） |

**关于第 9 项「发票及凭证」**：

- **推荐（免费方案）**：使用 **单行输入框**，标题仍为 `发票及凭证`。系统把本地附件文件名写入文本，审批人通过「详情链接」打开 H5 下载真实文件。
- **若使用「附件」控件**：标题改为 `附件`，并在 `.env` 设置：
  ```env
  DINGTALK_OA_ATTACHMENT_LABEL=附件
  ```
- 原生 OA 附件控件需钉盘 upload API；当前版本**未**自动上传钉盘，详见 [P4-OA对接指南](./P4-OA对接指南.md) §2 附件限制。

**常见错误**：`报销金额` 误设为「金额」、`费用发生日期` 误设为「发生日期」→ 会导致 OA 发起 API 报错，报销单保持草稿。

### D.3 审批流程设计（示例）

1. 切换到 **流程设计**。
2. 示例链路（可按企业实际调整）：

```
发起人（提交人）
    ↓
审批人 1：项目经理（按项目或指定成员）
    ↓
审批人 2：财务（指定财务角色或固定人员）
    ↓
结束
```

3. **抄送**（可选）：抄送区域负责人。
4. **条件分支**（可选）：大额走额外节点——本系统不解析分支条件，仅发起标准实例。

### D.4 发布模板并获取 processCode

1. 点击 **发布** / **启用** 模板。
2. 发布后，在模板详情或开放平台 **OA 审批** 关联处找到 **processCode**，格式：`PROC-XXXX-XXXX`。
3. 复制完整 processCode。

## E. 事件订阅（Stream 推荐 + HTTP 备选）

OA 审批完成后，钉钉需把结果**回写**到本系统。支持 **Stream 长连接**（推荐）与 **HTTP 回调**（备选），可并存。

### E.1 Stream 模式（推荐，免公网入站）

#### E.1.1 开放平台配置

1. 开放平台 → 你的应用 → **开发配置** → **事件订阅**。
2. 订阅方式：选择 **Stream 模式**（非 HTTP 推送）。
3. 点击 **添加订阅事件**，搜索并勾选：
   - **`bpms_instance_change`**（审批实例状态变更）
4. （可选）添加事件过滤，缩小范围：
   - `/v1.0/event/bpms_instance_change/processCode/{你的processCode}/type/finish`
   - `/v1.0/event/bpms_instance_change/processCode/{你的processCode}/type/terminate`
5. **保存** 配置。

#### E.1.2 后端启用 Stream

`backend/.env`：

```env
DINGTALK_STREAM_ENABLED=true
```

确保 `DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET` 已填写。

#### E.1.3 重启并验证连接日志

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\backend"
npm run dev
```

**期望日志**（连接成功）：

```
[stream] 钉钉事件 Stream 已连接（OA 审批回写）
```

**失败时常见日志**：

| 日志 | 原因 |
|------|------|
| `[stream] 钉钉凭证未配置，跳过 Stream 订阅` | AppKey/Secret 为空 |
| `[stream] DINGTALK_STREAM_ENABLED=false，跳过` | 环境变量为 false |
| `[stream] 连接失败: ...` | 凭证错误、网络出站被防火墙拦截 |

#### E.1.4 API 侧确认

```powershell
curl http://localhost:3000/api/config/approval
```

期望：`streamEnabled: true`，连接成功后 `streamConnected: true`。

---

### E.2 HTTP 回调（备选，需公网 HTTPS）

适用于无法使用 Stream、或需双通道冗余的场景。

#### E.2.1 开放平台配置

1. **事件订阅** → 选择 **HTTP 推送**（可与 Stream 并存，但需分别保存）。
2. **请求网址 URL**：

```
https://reimb.example.com/api/webhooks/dingtalk/oa
```

> 开发环境本地 `http://localhost:3000` **无法**通过钉钉 URL 验证，须用 HTTPS 穿透或生产域名。

3. 系统生成 **Token**、**EncodingAESKey**，复制保存。
4. 订阅事件：同样勾选 **`bpms_instance_change`**。
5. 点击 **保存**；钉钉会向 URL 发送验证请求。

#### E.2.2 写入 .env

```env
DINGTALK_CALLBACK_TOKEN=your_token_from_console
DINGTALK_CALLBACK_AES_KEY=43chars_encoding_aes_key_from_dingtalk_console
DINGTALK_CORP_ID=dingxxxxxxxx
```

`DINGTALK_CORP_ID` 须与解密 CorpId 一致（通常与企业 ID 相同）。

#### E.2.3 重启 backend

验证通过后，控制台显示 URL 验证成功。后端路由：

- `GET/POST /api/webhooks/dingtalk/oa`
- 状态检查：`GET /api/webhooks/dingtalk/oa/status`

```powershell
curl http://localhost:3000/api/webhooks/dingtalk/oa/status
```

期望：`encryptionConfigured: true`（生产配置 Token/AES 后）。

## F. 切换方案 B 并联调

本系统两种审批模式：

| 模式 | 说明 |
|------|------|
| **A** | 自研 H5 待办审批，不调用钉钉创建 OA API |
| **B** | 提交后创建钉钉 OA 单，Stream/HTTP 回写状态（**生产默认**） |

### F.1 将 approval.mode 设为 B

**开发环境注意**：`npm run db:seed` 在非 production 下**强制**把 `approval.mode` 设为 **A**（因 `dev_user` 无法发起真实 OA）。联调方案 B 需手动改回。

**方式 1：SQL（联调常用）**

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u reimb -p reimbursement -e "UPDATE sys_config SET config_value = 'B' WHERE config_key = 'approval.mode';"
```

**方式 2：环境变量 + 生产 seed**

```env
NODE_ENV=production
APPROVAL_MODE=B
```

```powershell
cd backend
npm run db:seed-prod
```

**方式 3：仅 .env 覆盖（重启后 seed-dev 会再次改 A，开发慎用）**

```env
APPROVAL_MODE=B
```

**验证**：

```powershell
curl http://localhost:3000/api/config/approval
```

期望：

```json
{
  "data": {
    "mode": "B",
    "processCodeConfigured": true,
    "dingtalkCredentialsConfigured": true
  }
}
```

### F.2 使用真实钉钉用户（非 dev_user）

| 登录方式 | `ding_user_id` | 能否发起 OA |
|----------|----------------|:-----------:|
| 浏览器 dev-login | `dev_user` | ❌ 自动降级 A |
| 钉钉客户端打开 H5 | 真实 userid | ✅ |

**真机联调步骤**：

1. 确认应用已发布，测试员工在可见范围内。
2. 手机钉钉 → **工作台** → 打开 **园林协作报销**（或你的应用名）。
3. 应**自动免登**（不出现「开发测试员」）；若仍走 dev-login，说明不在钉钉容器内或首页 URL 错误。
4. 新建报销 → 选项目 → 填金额 → **提交**。

### F.3 端到端联调检查表

| 步骤 | 操作 | 期望结果 |
|:----:|------|----------|
| 1 | 真实员工 H5 提交报销 | 报销单状态 → `approving` |
| 2 | 钉钉 **OA 审批** 待办 | 出现对应审批单，字段与 H5 一致 |
| 3 | 项目经理 **同意** | OA 流转到财务 |
| 4 | 财务 **同意** | OA 结束 |
| 5 | H5 报销详情 | 状态 → `approved`，审批时间线更新 |
| 6 | 预算 | `budget_ledger` 占用生效（若已配预算） |
| 7 | 后端日志 | Stream 收到 `bpms_instance_change` 无报错 |

**查 OA 映射表**：

```powershell
& "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u reimb -p reimbursement -e "SELECT reimbursement_id, process_instance_id, sync_status, LEFT(raw_create_response, 80) FROM dingtalk_oa_mapping ORDER BY id DESC LIMIT 5;"
```

| sync_status | 含义 |
|-------------|------|
| `synced` | 已成功发起 OA |
| `failed` | 发起失败，看 `raw_create_response` |
| `finished` / `rejected` | 已回写终态 |

### F.4 开发模拟：simulate-oa-event.js

无真机或需回归事件处理逻辑时使用：

```powershell
cd "f:\obsidian知识库\cursor\dingtalk-reimbursement\backend"

# 直接调服务层（需已有 dingtalk_oa_mapping 记录）
node scripts/simulate-oa-event.js --reimbId=1 --type=finish --result=agree

# 经 HTTP 模拟 webhook
node scripts/simulate-oa-event.js --reimbId=1 --type=finish --result=agree --http=true
```

**参数说明**：

| 参数 | 取值 |
|------|------|
| `--reimbId` | 报销单 ID |
| `--type` | `start` \| `finish` \| `terminate` \| `delete` |
| `--result` | `agree` \| `refuse`（`type=finish` 时） |
| `--http=true` | 走 `POST /api/approvals/webhooks/oa-instance` |

也可运行自动化：`npm run verify:p4`、`npm run verify:p4-http`。

### F.5 GET /api/config/approval 完整字段说明

| 字段 | 含义 |
|------|------|
| `mode` | 当前 `A` 或 `B` |
| `processCodeConfigured` | 是否已配置 processCode |
| `processCodeMasked` | 脱敏 processCode |
| `streamEnabled` | 是否启用 Stream |
| `streamConnected` | Stream 是否已连接 |
| `webhookEncryptionConfigured` | HTTP 回调加密是否配置 |

| `attachmentFieldLabel` | 附件控件 label，默认 `发票及凭证` |
| `dingtalkCredentialsConfigured` | AppKey/Secret 是否已填 |

## H. 故障排查 FAQ

### H.1 401 / 无效的 clientId 或 clientSecret

**现象**：

- 免登失败
- 日志：`[notify] 无效的clientId或者clientSecret` 或 Stream `[stream] 连接失败`
- 钉钉 API 返回 401

**排查步骤**：

1. 核对 `.env` 中 `DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET` 与开放平台 **AppKey/AppSecret** 完全一致（无空格、无引号）。
2. 若曾在开放平台 **重置 AppSecret**，须更新 `.env` 并重启 backend。
3. 确认应用属于**当前企业**的 CorpId，与 `DINGTALK_CORP_ID` 一致。
4. 确认应用**已发布**，非草稿状态。

---

### H.2 OA 发起失败 / 字段不匹配

**现象**：

- 提交后提示：`钉钉 OA 审批发起失败`
- `dingtalk_oa_mapping.sync_status = failed`
- `raw_create_response` 含 `formComponent` / `label` 相关错误

**排查步骤**：

1. 对照 [P4-OA对接指南](./P4-OA对接指南.md) §2 与本文 **D.2**，逐字核对 9 个 label。
2. 检查 `报销金额` 控件类型为 **数字**，不是单行文本。
3. 检查 `费用发生日期` 为 **日期** 控件。
4. 若附件控件名为「附件」，设置 `DINGTALK_OA_ATTACHMENT_LABEL=附件`。
5. 确认 `DINGTALK_PROCESS_CODE` 与**已发布**模板一致（非草稿 processCode）。
6. 确认已申请 **工作流实例写** 权限且管理员已审批。

**本地验证表单 label**：

```powershell
cd backend
npm run verify:p4
```

期望含：`[ok] buildReimbursementFormValues labels`。

---

### H.3 审批完成但 H5 状态不回写

**现象**：

- 钉钉 OA 已审完，H5 仍显示「审批中」
- `dingtalk_oa_mapping.sync_status` 仍为 `synced`

**排查步骤**：

1. 查 backend 日志是否有 `[stream] 钉钉事件 Stream 已连接`；若断连，重启 backend。
2. `curl http://localhost:3000/api/config/approval` → 确认 `streamConnected: true`。
3. 确认事件订阅包含 **`bpms_instance_change`**。
4. 若用 HTTP 回调：确认 URL 公网可达、HTTPS 有效、Token/AES 与控制台一致。
5. 查 `process_instance_id` 是否与 OA 单一致：

```sql
SELECT * FROM dingtalk_oa_mapping WHERE reimbursement_id = <你的ID>;
```

6. 用模拟脚本验证回写链路：

```powershell
node scripts/simulate-oa-event.js --reimbId=<ID> --type=finish --result=agree
```

---

### H.4 dev_user 自动降级为方案 A

**现象**：

- 已配置 processCode、mode B，提交后仍走 H5 待办，无钉钉 OA 单
- 日志：`[oa] 发起人非真实钉钉用户，降级为方案 A`

**原因（设计行为）**：

- 浏览器 `dev-login` 用户 `ding_user_id = dev_user`，**不是**真实钉钉 userid。
- `seed-dev` 在非 production 下将 `approval.mode` 设为 **A**。

**处理**：

1. 联调方案 B：SQL 改 `approval.mode = 'B'`（见 F.1）。
2. 使用**钉钉客户端**打开微应用，用真实员工身份提交。
3. 生产环境使用 `db:seed-prod`，不含 dev_user，用户首次钉钉登录自动创建 `user_account`。

---

### H.5 其他常见问题速查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 提交后无 OA 单 | mode 仍为 A；processCode 空 | F.1 + D.5 |
| HTTP 回调验证失败 | 非 HTTPS；防火墙拦截 | G.4 |
| 免登后白屏 | 前端未部署；URL 缺 `/h5/` | 检查 Nginx / Vite |
| `[stream] 钉钉凭证未配置` | `.env` 未填 Key/Secret | B.4 |
| 模板重建后失效 | processCode 变更 | 更新 `DINGTALK_PROCESS_CODE` 并重启 |
| 工作通知失败 | 未申请消息权限 | C.4 |
